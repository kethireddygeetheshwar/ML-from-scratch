# Contributing

Thanks for contributing to ML-from-scratch.

## Development workflow

1. Create a focused branch for your change.
2. Keep each algorithm implementation small and explain the mathematics in the notebook or module.
3. Add or update tests when reusable Python code is introduced.
4. Include experiment results when changing an algorithm or training procedure.
5. Run the notebooks or relevant tests locally before opening a pull request.

## Pull requests

A useful pull request should explain:

- what changed;
- why the change is useful;
- how it was tested; and
- any trade-offs or limitations.

Avoid adding dependencies unless they are necessary for the learning objective.
